✅ Sensitive Actions (should go through Edge Functions)
Use Edge Functions to validate auth, confirm ownership, or run secure logic.
Cart merging → must confirm both carts belong to same user or valid transfer.
Visitor identity promotion → e.g. replacing visitor_uuid with user_id.
Creating/updating stripe_customer_id → must validate user match.
Checkout pre-validation → before creating a Stripe Checkout session.
Any action that updates cross-user data → e.g. reassigning carts, orders.
Soft-to-auth transitions → where ownership changes or identity links.
Webhook verification handlers → to prevent spoofed requests from faking Stripe events.

⚪ Non-Sensitive Actions (can use direct Supabase client + RLS)
These are read/write actions scoped to current session, where RLS protects the data.
Reading or writing to current cart → as long as scoped to visitor_uuid via JWT.
Adding items to cart → tied to current visitor only.
Storing email/phone to existing visitor → no cross-record write risk.
Reading invoices or subscriptions for logged-in user → via filtered auth.uid.
Simple flag updates (e.g., has_seen_intro) → scoped, harmless writes.

Rule of thumb:
If the action alters ownership, crosses identity boundaries, or touches billing, it’s sensitive → use Edge Function.
If it’s local, scoped, and guarded by RLS, it’s not.
