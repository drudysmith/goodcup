Repair No. 1 – Contact popup shows despite user session
Summary
The cart-hover logic always displays ContactInfoPopup when visitor data lacks email/phone/name. When a Supabase user session exists, VisitorProvider skips visitor auth, so visitorReady becomes true but visitorData is null. This combination triggers the popup even while the user is logged in.
Where to Look
components/Layout.tsx – useEffect checking cartHovered and visitorReady around line 509
lib/contexts/VisitorContext.tsx – session check sets skipVisitor to true around line 84
Implementation Notes
Update the popup logic to also verify there is no active Supabase session before showing the popup.
The visitor context’s skipVisitor flag can be used to detect an existing session.
Breakpoint/Bugwatch/Testing
With a session active, hover over the cart; the popup should not appear.
Ensure the popup still works for guests without a session or contact info.

Repair No. 2 – Address data saved repeatedly
Summary
handleContinueToShipping saves the address every time the “Continue to Shipping” button is clicked, even when the address hasn’t changed. This results in extra writes.
Where to Look
pages/checkout.tsx – handleContinueToShipping around lines 406‑439, including the console log “📍 Module 6f: Saving address information”
Implementation Notes
Compare the current form values with previously saved address data (from visitor profile or user profile). Only mutate when there is a difference.
Consider caching the last saved address locally to avoid unnecessary POST requests.
Breakpoint/Bugwatch/Testing
Verify that advancing to shipping once triggers one save.
Navigate back to the information step and forward again; confirm no additional save occurs unless the address has changed.
